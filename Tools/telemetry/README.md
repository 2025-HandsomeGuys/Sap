## viewer.html — 로그 뷰어 + 플레이 일지

**`viewer.bat` 을 더블클릭**하면 로컬 서버(127.0.0.1:8777)를 띄우고 브라우저가 열린다.
`AppData/LocalLow/<회사>/<제품>/telemetry` 를 **자동으로 찾아 붙는다** — 못 찾으면
폴더를 드래그하거나 `viewer.bat "폴더경로"` 로 열면 된다. 창을 닫으면 서버도 꺼진다.
로그는 로컬에서만 읽고 밖으로 나가지 않는다.

**게임을 켜 둔 채로 띄워 두는 도구다.** 서버가 `*.jsonl` 을 이어읽어(롱폴링) 새 줄을
바로 밀어주고, `day_settled` 가 뜨면 **그 일차 일지 작성 화면으로 자동으로 넘어간다.**

`viewer.html` 을 그냥 더블클릭해도 로그 열람은 되지만 **일지는 안 된다** — 저장할 서버가 없다.

`viewer.html` 을 그냥 더블클릭해도 대개 동작하지만, **VSCode 안의 미리보기(Simple Browser·
Live Preview)로 열면 안 된다** — `file:` URL은 브라우저가 각각 다른 오리진으로 취급해서
iframe 로드부터 막힌다(`'file:' URLs are treated as unique security origins`).
드래그가 안 먹히는 환경에서는 화면의 **폴더 선택 / 파일 선택** 버튼을 쓰면 되고,
그래도 안 되면 `viewer.bat` 이 확실하다.

핵심은 **`run_id` 로 회차를 다시 합치는 것**이다. 게임을 껐다 켜면 파일이 갈라지므로
하루치 플레이가 파일 4~5개에 흩어진다 — 파일 하나만 열어서는 회차를 볼 수 없다.

| 탭 | 보이는 것 |
|---|---|
| 개요 | 요약 타일 · 골드 추이 · 일자별 정산표(`day_settled`) · 지역 체류 · 환경 |
| 일지 | 진행 중인 일차의 사건 기록 · 미해결 목록 · 일차별 일지 |
| 다이브 | 다이브별 깊이·소요·판 픽셀·광물 내역·스태미나·지역 비중 |
| 경제 | 판매/구매 아이템별 집계 · 업그레이드 구매 · 거래 시간순 |
| 편의성 | 수입으로 못 재는 축(채굴·이동 속도, 벽타기, 스태미나 소모율)의 체감 지표. 구매 시점 ▲ 표시 |
| 에러 | 메시지별로 묶어서 횟수·발생 일차·스택 |
| 원본 | 이벤트 타입 필터 + payload 검색, 줄 펼치면 원본 JSON |

이벤트 시각은 **파일명(세션 시작 시각) + `playtime`** 으로 복원한다 —
파일명 규칙(`yyyyMMdd-HHmmss_<세션ID8자>.jsonl`)을 바꾸면 시각이 안 나온다.

CSV로 통계를 내는 건 `export_csv.py`, 한 회차를 눈으로 훑는 건 이 뷰어다.

## 플레이 일지

숫자는 "무슨 일이 있었나"만 말한다. **"그때 어떤 느낌이었나"는 그 자리에서 적지 않으면 사라진다.**
일지 탭이 그걸 받고, 저장 위치는 `journal/<run_id>.json` 이다(회차별 파일 1개).

### 한 일차가 흘러가는 모양

| 때 | 화면 | 적는 것 |
|---|---|---|
| 플레이 중 | 일지 탭 상단 **진행 중** 카드 | 오늘의 질문 · 사건(시각 자동) |
| 자면 | **자동으로 그 일차 1단** | 예상 vs 실제 · 그만두고 싶었던 지점 · 내일 또 켜고 싶은가 |
| 1단 제출 | 그 일차 **숫자 공개** | 표와 기억이 어긋난 곳 · 내일의 질문 |

`내일의 질문` 은 다음 일차 `오늘의 질문` 칸으로 자동으로 이월된다.

### ⚠ 숫자를 먼저 보여주지 않는 게 이 도구의 핵심이다

1단을 제출하기 전에는 **개요·다이브 탭에서도 그 일차 행을 가린다.** 표를 먼저 보면
기억이 숫자에 맞춰 왜곡되고, 만든 사람 본인이면 더 심하다. 급하면 `그냥 보기` 로 뚫을 수
있지만, 뚫고 나서 쓴 일지는 "숫자를 보고 쓴 감상"이지 관찰이 아니다.

같은 이유로 **1단 화면은 그날 표를 렌더링하지 않는다.** 여기에 숫자를 얹으면 도구가 하려던
일이 통째로 없어진다 — 순서를 바꾸지 말 것.

### 적는 규칙

- **관찰과 해석을 다른 줄에.** "엘베 찾느라 4분 걸음"(관찰)과 "정류장 X 폭이 넓어서"(해석)는
  다른 칸이다. 해석은 나중에 틀린 걸로 밝혀지는데, 섞어 적으면 관찰까지 같이 버려진다
- **해결책은 `안` 칸에만.** 사건 줄에 아이디어를 적으면 문제 정의가 아이디어에 맞춰 휜다
- **감정어를 다듬지 않는다.** "개선 필요" ✗ / "지겨워서 알트탭함" ○
- `고칠 것` 을 체크한 사건은 일지 탭 상단 **미해결** 목록에 쌓인다. 고치면 `고침` 체크

### 게임 쪽 연동

`day_settled`(수면)·`dive_end`(지상 복귀) 직후 `Telemetry.Flush()` 를 부른다
(`BedInteractable` / `SleepSequence` / `SettlementManager`). 기본 flush 주기가 60초라
이 줄이 없으면 자고 나서 최대 1분 뒤에야 일지 화면이 뜬다. 새 이벤트를 일지와 엮고 싶으면
같은 자리에 `Flush()` 를 붙이면 된다.

## 사용법

```
python export_csv.py <telemetry_dir> -o <out_dir> [--include-fixture]
```

`<telemetry_dir>` 는 게임의 `persistentDataPath/telemetry/` 다.
Unity 에디터에서 `Tools/Telemetry` 메뉴로 폴더를 열 수 있다.

Windows 기본 경로:
`%USERPROFILE%\AppData\LocalLow\<CompanyName>\<ProductName>\telemetry`

## 출력

| 파일 | 한 줄 |
|---|---|
| `days.csv` | 한 회차의 N일차 정산 1건 (`day_settled`) |
| `dives.csv` | 잠수 1회 (`dive_end`) |
| `upgrades.csv` | 업그레이드 구매·차단 1건 (`upgrade_purchased` / `upgrade_blocked`, `blocked` 컬럼이 가른다) |
| `failures.csv` | 사망·긴급탈출 1건 (`stamina_depleted` / `emergency_escape`, `kind` 컬럼이 가른다) |

⚠ **2026-08-31 이전 로그에는 사망한 잠수가 `dives.csv` 에 없다.** 그때는
`GameOverHandler` 가 `SettlementManager` 를 안 거쳐 `dive_end` 가 발화하지 않았다
(`dive_start` 212 vs `dive_end` 113). 지금은 `result="death"` 로 남는다.
옛 로그를 섞어 보면 그 구간만 **살아 돌아온 잠수만** 보이므로(생존 편향) 주의할 것.

⚠ `minerals` 는 *캔* 광물이지 *가져온* 광물이 아니다 — 긴급탈출은 60%, 사망은
전부 잃는다. **수입 계산은 `result == "return"` 인 잠수로만** 할 것.

표들은 `run_id` + `day` 로 조인된다.
`dives.csv` 를 `run_id, day` 로 group-by 하면 하루 요약이 나온다.

## 픽스처 제외

QA 픽스처(`fx load`)나 디버그 명령(`gold`/`day`/`stamina`)을 쓴 시점부터
그 회차의 이벤트에 `is_fixture=true` 가 붙는다. 익스포터는 **그 표시가 붙은 이벤트만**
기본적으로 뺀다 — 조작하기 전에 이미 쌓인 이벤트는 `is_fixture=false`인 정상 플레이
데이터라 표에 그대로 남는다. 회차 전체를 지우는 게 아니다.
전부 포함하려면 `--include-fixture`.

## 업그레이드 가격 재산정

```
python fit_upgrade_prices.py --csv-dir <out_dir> --nodes 9
```

`days.csv` 의 `mineral_sale` 을 그날 다이브 횟수로 나눠 회당 매출을 만들고,
`unlocked_nodes` 에 대해 최소제곱 직선을 적합한다 — `회당매출 ≈ base + growth × 노드수`.

그 곡선에 붙여 가격을 매기고, **"다이브마다 하나는 사지고 두 번째는 모자란다"** 규칙을
시뮬레이션으로 검사한다. 위반이 있으면 `--margin` 을 어느 쪽으로 돌릴지 알려준다.

수치를 직접 넣어 사다리만 볼 수도 있다:

```
python fit_upgrade_prices.py --income 100 --growth 8 --nodes 9
```

배경: `Assets/Docs/economy/mineral-price-design.md` §2.5-A / §2.5-B —
원래 예산은 모델값(회당 1,430G)에서 역산했는데 실측은 100G였다. 모델을 고치는 대신
**버는 만큼에 예산을 맞추기로** 결정했으므로, 측정할 때마다 이 도구로 다시 뽑는다.

## 원칙 판정 (`check_principles.py`)

```
python check_principles.py --csv-dir <out_dir>
```

업그레이드 트리가 원칙을 지키는지 판정하는데, **먼저 판정할 자격이 있는지부터 잰다.**

- **P0 — 모델-실측 정합**: `run_model.py`가 박아 둔 상수(`PX_PER_DEPTH`,
  `dig_px_per_swing`, 배터리 소모, 초당 스윙, 안전 마진)를 `dives.csv`에서 각각 다시 뽑아
  ±25% 안에 드는지 본다. 지배 노드·함정 같은 원칙은 전부 이 모델 위에서 판정되므로,
  여기가 FAIL이면 그 판정을 신뢰할 수 없다. **종료 코드 1.**
- **P12 — 판정 가능한 분산**: 같은 회차·같은 노드 수 잠수들의 변동계수를 재고,
  거기서 "각 n판을 모아야 몇 % 차이를 가릴 수 있는지"를 계산한다.
  **다른 원칙의 임계치가 여기서 나온다** — 감으로 정하면 PASS/FAIL이 동전 던지기가 된다.

- **티어 A** — P1(관문 외엔 하루 하나)·P2(업글하면 달라진다)·P3(회수 기간)·P6(벽 금지)·
  P8(실패 비용)·P9(성장 포화)·**P13(편의성 축)**. 임계치는 P12가 정한 값을 그대로
  받아 쓰고, P2·P3의 판정선은 **구간마다 그 표본 수로 다시 계산한다**(고정값이 아니다).

  P13은 수입으로 못 재는 축을 **체감 지표**로 잰다 — 채굴 속도는 초당 스윙,
  이동 속도는 깊이당 실시간, 벽타기는 매달린 시간, 소모율은 등반 초당 드레인.
  `climb_seconds`/`climb_stamina`는 2026-08-31에 추가된 계측이라 그 이전 로그엔 없다.

실측 결과와 확정된 임계치는 `Assets/Docs/economy/upgrade-balance-charter.md` §4-6.

⚠ `upgrade_blocked`는 2026-08-31 이전 로그에 한 건도 없다 — 코드는 배선돼 있었지만
호출부 세 곳이 전부 CanUnlock으로 먼저 막아 **도달할 수 없었다**. 지금은 고쳐졌고,
P6은 다음 플레이 데이터가 쌓이면 판정된다. charter §6-A.

혼자 플레이하는 동안 **구매 분포를 재는 원칙(지배 노드·빌드 다양성)은 무효다** —
트리를 만든 사람이 매번 같은 것을 사기 때문이다. 그 축은 텔레메트리가 아니라
`check_tier_b.py`가 런 모델의 반사실로 판정한다.

## 티어 B 판정 (`check_tier_b.py`)

```
python check_tier_b.py [--steps 20] [--variants 12]
```

`UpgradeTree.csv`의 노드와 **사람이 맞춘 가격**을 런 모델이 채점한다.
가격을 다시 굽지 않는다 — `reprice_template.py`를 부르지 않는다(charter §1).

**`check_principles.py`의 P0가 PASS일 때만 믿을 것.** 판정이 전부 모델 위에 서 있다.

⚠ 66노드 중 30개만 채점된다. `income()`이 배터리·범위·무게·면허·판매가만 쓰기 때문에
채굴 속도·벽타기·이동 속도 노드는 **사각지대**다 — 체커가 필드를 탐침해
'함정'과 '못 봄'을 가른다. 자세한 것은 charter §7.

## 파생 컬럼

시간당 광물·긴급탈출률·파산 임계값 같은 파생값은 CSV에 넣지 않는다.
정의가 계속 바뀌므로 엑셀/노트북에서 계산한다.

예) 긴급탈출률 = `dives.csv` 에서 `result == "escape"` 비율을 `day` 로 group-by
