# 손에 집기(Held Item) 시스템 — 코드 오버레이용

창고(`WarehouseOverlayUI`)·지하 인벤토리(`InventoryOverlayUI`)에서 **좌클릭으로 스택을 손에 집고,
우클릭으로 1개씩 내려놓고, 마우스 휠로 개수를 조절**하는 조작을 되살린 시스템.

핵심 구현: `Assets/Scripts/UI/Core/CodeHeldItem.cs`

## 왜 새로 만들었나

옛 `HeldItemManager`(+`InventorySlotClickHandler`)는 **프리팹 UI**(`InventoryUI`/`WarehouseUI`) 전용이라
지금의 코드 생성 오버레이(`CodeSlotView` 기반)에는 붙지 않는다. 그래서 `CodeSlotView`를 다루는
새 컨트롤러 `CodeHeldItem`을 만들었다. 옛 파일들은 건드리지 않았다(다른 경로에서 여전히 컴파일됨).

## 불변식 — 집는 순간엔 데이터를 안 건드린다

`CodeHeldItem`은 집을 때 인벤토리에서 아이템을 **빼지 않는다.** 손에 든 개수(`_qty`)만 추적하고,
- 원위치 반납(휠 아래·우클릭 원본·좌클릭 원본)은 **`_qty` 감소만** — 데이터 변화 없음.
- 실제 이동/버리기는 **호스트(오버레이)의 기존 이동 로직**(`MoveBetween`/`Withdraw`/`Deposit`/`AskDiscard`)을
  그대로 호출한다. 덕분에 무게 한도·창고 용량·스왑·세이브 정합성이 기존 클릭/드래그와 **완전히 동일**하다.

닫기·씬 전환·ESC·빈 곳 클릭 시 손을 비워도 원본이 그대로 있으므로 손실이 없다.

### 원본 칸은 '남은 개수'를 보여준다 (시각 분할)

데이터는 안 빼지만, **표시는 나눈다.** `CodeSlotView.ApplyHeldAwareContent()`가 집어 든 원본 칸을
`전체 − 손에 든 개수`로 그린다(`CodeHeldItem.IsSource`/`HeldQuantity` 조회). 집는 순간엔 '남은 0'(빈 것처럼
흐림), 휠을 내리면 원본의 수량이 하나씩 늘고 고스트(손)는 하나씩 준다. 커밋하면 **손에 든 개수만** 이동한다.
이 held-aware 렌더링은 `Bind`에도 들어 있어 오버레이가 새로고침해도 분할 표시가 유지된다.

## 조작

| 입력 | 빈 손 | 손에 든 상태 |
|------|-------|--------------|
| 좌클릭(칸) | 스택 전부 집기 | 그 칸에 전부 내려놓기(다른 아이템이면 맞바꿈→손 비움) |
| 우클릭(칸) | 스택 전부 집기 | 그 칸에 1개 내려놓기(원본이면 1개 반납) |
| 마우스 휠 | 목록 스크롤 | 위=1개 더 집기 / 아래=집은 자리로 1개 반납 |
| 쓰레기통 클릭·드롭 | (드롭) 전량 버리기 | 손에 든 개수만 버리기(확인 팝업) |
| ESC / Tab | 닫기 | 손 비우기(닫히지 않음) |
| 빈 곳 좌클릭 | — | 손 비우기 |

- **드래그는 그대로**: `CodeSlotView`의 자유 이동·스왑은 손과 무관하게 작동한다. 단 손에 든 동안엔
  드래그를 시작하지 않는다(고스트 중복 방지, `CodeSlotView.OnBeginDrag` 가드).
- **키보드(스페이스)는 손을 안 쓴다**: 마우스 고스트가 없어 어색하므로 옛 방식(즉시 전량 이동)을 유지한다
  (`WarehouseOverlayUI.NavActivateSlot`).

## 호스트 계약 — `CodeHeldItem.IHost`

오버레이가 구현한다. 손 상태 관리·고스트·전역 입력은 컨트롤러가, 실제 인벤토리 변경은 호스트가 맡는다.

- `HeldCommit(source, target, amount)` : `amount`개를 옮기고 **손에서 덜어낸 개수**를 반환.
  스왑/소진처럼 손을 통째로 비워야 하면 `int.MaxValue`, 실패면 0. (창고는 `MoveBetween` 앞뒤로 원본 슬롯
  수량을 읽어 계산 — 아이템이 바뀌면 `MaxValue`.) **지하는 옮길 곳이 없어 항상 0**(집기→반납·부분 버리기 전용).
- `HeldTrash(source, amount)` : 그 칸을 `amount`개 버린다(호스트 확인 팝업).
- `HeldLiveQuantity/ItemId` : 원본 칸의 라이브 수량·아이디(휠 상한·정합성 판정).
- `HeldScrollRect` : 손에 든 동안 잠글 목록 스크롤. `HeldHostOpen`/`HeldRefresh`/`HeldPlaySfx`.

## 범위 / 예외

- 창고: 광물·아이템·장비 칸 전부 집기 가능. **유물 로드아웃·창고 유물 칸은 클릭=장착/해제**를 유지(스택 개념이
  없어 손에 안 집는다).
- 지하 인벤토리: 광물·아이템 칸 집기 가능(옮길 창고가 없어 **개수 조절→쓰레기통 부분 버리기·원위치 반납**이 용도).
  장비·유물은 지하에서 못 벗으므로 표시 전용 그대로.
- 창고 내부(창고→창고) 부분 이동: `WarehouseManager.MovePartial(from, to, amount)`이 그만큼만 옮긴다
  (빈 칸=그만큼 새로 놓기 / 같은 스택=합치기 / 다른 아이템=부분 불가). **전량**일 때만 기존 `MergeOrSwapSlots`로
  병합·스왑한다(드래그와 동일). `MoveBetween`이 `amount >= 전체` 여부로 둘을 가른다.
- 남은 예외: 창고 아이템을 **다른 아이템이 든 가방 칸**에 부분(하나씩) 내려놓으면 `TrySwapWithBagItem`이 전량 스왑한다
  (드래그와 동일). 보통 빈 칸에 놓으므로 드묾.
